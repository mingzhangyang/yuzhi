# 现实生活培育区：开放设计文档

状态：**Open**  
分支：`feat/real-life-cultivation`  
日期：2026-10-05

## 1. 目标

屿志不引入传统模拟经营。用户不能直接点击“浇水、施肥、喂鱼、修剪”来经营小岛；用户继续过自己的现实生活，系统把已经存在的真实行为映射成岛上的生长。

本轮新增四个长期培育区：

- **农田**：由 Todo / 任务的真实推进培育。
- **果园**：由日程（日历导入 + 用户自己创建）的安排与兑现培育。
- **鱼塘**：由最近一段时间的生活节律与结算记录培育。
- **花园**：由日记 / 反思记录培育。

同时补齐三种一等输入：

- 用户可在屿志里**创建日程**，不必只依赖外部 .ics。
- 用户可写**日记**。
- Todo / 任务继续保留，并在文案与培育映射里明确为 Todo。

## 2. 产品底线

1. **不能直接经营。** 培育区没有浇水、施肥、喂鱼、修剪、收获按钮。
2. **现实事实是唯一输入。** 视觉长势只能由任务、日程、日记、结算等业务事实推导。
3. **培育状态是 read model。** 不把“农田等级”“鱼塘等级”单独写入数据库；事实变化后重新计算。
4. **不增加维护负担。** 创建日程、日记、Todo 本身就是用户想记录的现实信息，不为小岛额外造打卡任务。
5. **不与项目衰败混淆。** 村落继续表达“项目推进 / 停滞”；培育区表达更横向的生活行为。
6. **恢复快、惩罚弱。** 长势可以随近况缓慢回落，但不枯死、不清零历史，也不制造羞耻反馈。
7. **任何映射都可解释。** 培育区应能说明“它为什么现在长成这样”。

## 3. 核心循环

```
现实输入
  ├─ 日历事件 / 创建日程
  ├─ Todo / 项目任务
  ├─ 日记
  └─ 每日结算
        ↓
规则读取事实
        ↓
四类培育信号
        ↓
农田 / 果园 / 鱼塘 / 花园的可见长势
        ↓
用户观察、裁决、继续生活
```

核心逻辑仍然是：

> **观察 → 裁决 → 回应 → 记忆**

而不是：

> 操作 → 奖励 → 重复操作

## 4. 映射规则

### 4.1 农田：做事

含义：把想做的事情真正推进。

输入：

- 最近 14 天结算为 `done` 的任务：2 点
- 最近 14 天结算为 `partial` 的任务：1 点

不计：

- 只创建但没有推进的 Todo
- 被放下 / 不重要了的任务
- 日历事件

视觉语义：

- 0：休耕
- 1：翻过的土
- 2：出苗
- 3：作物长高
- 4：成熟、出现麦穗 / 草垛

### 4.2 果园：安排时间

含义：现实中的时间结构逐渐稳定，计划不是抽象列表，而是被放进一天里的时间。

输入：

- 今天前后 7 天内的定时日程（外部日历和本地创建日程都算），按“有安排的天数 + 已结算兑现”形成信号。
- 已结算 `done` 的日程比单纯存在的未来安排权重更高。
- `partial` 有较轻权重。
- 全天事件只作为背景信息，不用于刷长势。

视觉语义：

- 0：幼树 / 稀疏
- 1：发芽
- 2：枝叶增多
- 3：开花
- 4：结果

### 4.3 鱼塘：生活节律

含义：不是“完成更多”，而是持续留下对一天的真实记录，形成可感知的生活节律。

输入：

- 最近 14 天中被用户正式结算的天数。
- 结算内容可以有做了、没做、没精力、不重要了；鱼塘不评价结果好坏，只认“这一天被诚实记录过”。

不计：

- 自动归档为“未记录”的日子。

视觉语义：

- 0：浅水、安静
- 1：水面恢复
- 2：出现水草 / 涟漪
- 3：能看见鱼群
- 4：水清、鱼群活跃

这让“承认今天没精力”仍然可以维护鱼塘，不把自我记录变成绩效考核。

### 4.4 花园：记录自己

含义：把经历、感受和线索写下来。

输入：

- 最近 30 天有日记的“不同日期数”，一天无论写几篇只计一次。
- 内容长度不影响长势，避免鼓励灌水。

视觉语义：

- 0：空花圃
- 1：嫩芽
- 2：零星花朵
- 3：成片开花
- 4：花园繁盛

## 5. 数据模型

### 5.1 日记

新增事实集合：

```ts
interface DiaryEntry {
  id: string;
  date: ISODate;
  text: string;
  createdAt: string;
}
```

日记是业务事实，进入 IndexedDB 和 JSON 备份。

### 5.2 本地日程

不建立第二套日程模型。用户创建的日程直接复用 `CalendarEvent`，使用保留来源：

```ts
sourceId = "local"
```

特点：

- 继续进入现有 agenda / 晚间结算 / 归类 / 粮仓逻辑。
- 默认由用户创建时确定项目或杂务归属，所以 `classified = true`。
- 外部 .ics 和本地日程在后续规则层没有特权差异。

### 5.3 培育状态

**不持久化。**

新增纯函数：

```ts
cultivationState(data, today) -> {
  field,
  orchard,
  pond,
  garden
}
```

每个区域返回 `score`、`level 0..4` 和可解释的摘要。

## 6. 交互

顶部“＋ 新建”不再只等于“新任务”，而是打开一个轻量入口：

- Todo
- 日程
- 日记
- 项目

### Todo

沿用现有任务创建逻辑，可选村落和日期。

### 日程

至少包含：

- 标题
- 日期
- 开始时间
- 结束时间
- 归属：某个项目 / 杂务

创建后立即进入当天日程与 Canvas “此刻层”；结束后仍需要晚间结算，不能自动算完成。

### 日记

至少包含：

- 日期（默认今天）
- 正文

写下后花园 read model 立即重算。日记不进入晚间结算，不产生“完成 / 失败”。

## 7. Canvas

四个培育区是岛上的固定公共区域，不占村落槽位，也不随项目关闭而消失：

- 农田：靠近现有田地 / 水源
- 果园：独立的成片果树
- 鱼塘：独立水面
- 花园：靠近生活区的花圃

绘制只读取 `Scene.cultivation`。

要求：

- 四个区域在 level 0 时也存在，只是安静 / 稀疏。
- level 越高，增加密度、成熟度和细节，不用夸张粒子奖励。
- 点击或键盘浏览时可以解释来源，例如：
  - “最近 14 天推进了 4 件 Todo，农田正在长高。”
  - “最近 30 天有 6 天写过日记，花园开了更多花。”
- 季节、天气仍可影响配色，但**不能覆盖现实行为决定的长势等级**。

## 8. 历史与衰减

培育区看的是滚动窗口，因此会随现实近况自然变化。

这不是惩罚：

- 老成果仍留在项目的一生之书、地标、档案馆和编年史。
- 培育区只回答“最近的生活在怎样滋养这座岛”。

## 10. 仍开放的问题

以下问题保持 Open，后续根据真实使用调整，不阻塞本轮：

1. 四类窗口长度（14 / 7 / 14 / 30 天）是否合适。
2. 果园是否应该更强调“兑现日程”而减少“创建安排”的权重。
3. 鱼塘未来是否引入“可用时间 / 过载”信号；当前版本只认诚实结算，避免把休息误判成低质量生活。
4. 日记未来是否允许手动关联项目；当前先作为岛级输入。
5. 四块培育区是否需要进入编年史的阶段变化；当前不写，避免噪声。

## 11. 验收标准

- 用户不做任何新增“经营动作”，四个区域仍会随着真实记录发生变化。
- 创建本地日程后，它和导入日历一样出现在日程层，且过去后必须由用户结算。
- 写日记后花园状态变化，但不会制造待办或结算项。
- 完成 Todo 后农田状态变化；只创建 Todo 不会让农田成熟。
- 对一天如实结算，即使全部“没做”，鱼塘仍认可这一天被记录。
- 删除 / 修改底层事实后，培育 read model 随事实重新计算，不存在需要同步维护的第二份“培育等级”。
