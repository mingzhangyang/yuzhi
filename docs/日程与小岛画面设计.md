# 日程与小岛画面：对应关系设计

状态：草案（2026-10-04；第 7 节前三项已定）　范围：日历事件（`CalendarEvent`）在 Canvas 小岛上的全部表现，以及由日程引起的转场动画。

本文是独立的设计 RFC，不延长 Architecture v2 计划。数据模型、持久化、结算规则都**不改**；改的是「画面读什么、怎么读」。

---

## 1. 问题

交接文档第 6 节写的是：

> **日历事件**：告诉小岛时间花在了哪里。决定村落热闹还是冷清。

现在的实现只做到了后半句的「事后版本」：日程只有经过晚间结算变成 `SettlementEntry`，才会影响砖、房子和衰败。白天打开小岛，看不出今天的时间花在哪里：

| 现状 | 问题 |
|---|---|
| 正在开会的项目，村落和平时一样 | 小岛不反映「此刻」 |
| 小人只代表任务 | 一个只靠会议推进的项目，村落空空荡荡 |
| 杂务只有一个数字标签 | 杂务占掉的时间在画面上看不到 |
| 没归类的事件在地图上看不到 | 归类入口只在弹窗和追踪栏里 |
| 衰败换阶段、海雾增减、粮仓变化都是直接跳变 | 后果发生了，用户却没看到它发生 |
| 动画触发点分散在 `main.ts`（DOM 砖块）、`render.ts`（pulse、grow）和 CSS | 没有一处地方回答「哪个事实触发哪个动画」 |

同时有一条**已定决定**必须守住（交接文档第 7 节）：

> 过去的事件和任务不会默认算完成，需要用户确认。

所以设计的核心矛盾是：**让日程实时地出现在岛上，又不让它在用户确认之前产生任何后果。**

---

## 2. 设计原则

1. **三层分开，互不越界。**
   - **此刻层**：由「当前时刻 + 日程」推出，只存在于画面上，不写库、不进指标、不进衰败。回答「时间现在花在哪」。
   - **后果层**：只由结算事实（`entries`、`operations`、`days`）决定，规则保持不变。回答「这些日子留下了什么」。
   - **转场层**：后果层的值变化时，播放一次性的过渡。回答「刚刚发生了什么」。
2. **此刻的画面不能像后果。** 此刻层只用「人聚在一起」「灯亮着」「东西漂着」这类状态；砖、房子、灰尘、杂草只属于后果层。用户不会误以为会议开完房子就长了。
3. **一个元素只表达一个事实。** 小人一直等于任务，不另加「会议访客」小人；船一直等于码头上的任务，不拿来表示未归类事件。
4. **默认安静。** 同一时刻全岛最多一处吸引注意力（例如铃声的涟漪）；`prefers-reduced-motion` 下，此刻层只保留静态状态，转场直接到终态。
5. **地图上的东西都能点开解释。** 每个新元素都接 `hitAt` / `info.ts`，说明它来自哪条日程，以及「结算确认后才算数」。

## 3. 一条日程的一生

按两条轴分类：**时间阶段**（相对当前时刻）× **归属**（项目 / 杂务 / 未归类 / 全天）。

```
今天稍后 ──► 即将开始 ──► 进行中 ──► 已结束·待结算 ──► 已结算（做了 / 一部分 / 没做）
 (later)     (soon,≤15分)   (live)      (ended)            或 3 天后归档「未记录」
```

### 3.1 对应总表

| 阶段 \ 归属 | 项目村落 | 杂务 | 未归类 | 全天 |
|---|---|---|---|---|
| **今天稍后** | 村口井旁立一块**告示牌**，牌上的刻痕数 = 今天剩余场次 | 杂务小屋门口挂一把**扫帚** | 近岸海面漂着**漂流瓶**（数量 = 还没捞起的未归类组数，最多 3 个，见 3.4） | **条幅**（见 3.5）：今天在事件区间内就挂，整天不变 |
| **即将开始** | **钟声**：井架上的铃摇一下，荡开一圈涟漪（全岛同时只响一处，见 3.6）；村里的人开始朝井走 | 小屋门打开 | 同上 | — |
| **进行中** | **井边集会**：村里的小人围着井站成一圈，井边点一盏灯；标签变成「团队 · 周会 至 15:00」 | 小屋窗户亮灯，门前有扫地的动作；标签「杂务 · 买菜」 | 同上 | — |
| **已结束·待结算** | 井边留一摞**砖坯**（浅色、未烧），数量 = 今天已结束但没结算的场次 | 门口一小捆**柴** | 同上 | — |
| **结算：做了** | 砖坯烧成砖：现有的 DOM 砖块飞入 → `pulse` → 够 3 块盖新房（现有 `grow`） | 柴放进柴堆（见 3.3），不飞砖 | 结算卡显示「未归类」，不飞砖（不变） | — |
| **结算：一部分** | 砖坯变成半块砖飞入 | 同「做了」 | 同上 | — |
| **结算：没做** | 砖坯淡出，不留痕迹；原因的后果维持现有规则 | 柴淡出 | 同上 | — |
| **归档未记录** | 砖坯随海雾消散，无后果 | 同左 | — | — |

### 3.2 为什么这样选

- **井**：每个村落中心本来就有井（`drawWell`），而「人聚在井边」天然就是「时间花在这里」。
- **不用炊烟**：`drawHouse` 已经用炊烟表示冷天、阴雨和傍晚，再拿它表示开会，含义会重叠。
- **砖坯 → 砖**：把「日程结束」和「结算」接成一个连续的物理过程，直观说明「开过会 ≠ 盖了房」，要你确认才烧成砖。
- **衰败中的村落照样开会**：蒙灰村落里正在开会时，人照样聚到井边，但灰尘和杂草不会变（不提前恢复）。这正是「时间花在这里，但还没确认推进」。
- **村里没有小人时**：没有未完成任务的村落开会时，井边只亮灯、不聚人，避免凭空造人（原则 3）。

### 3.3 杂务：柴堆

杂务不建造东西，但会消耗精力。小屋旁的**柴堆**取代现在的纯数字：近 7 天已结算的杂务越多，柴堆越高（分 0 / 1–3 / 4–8 / 9+ 四档），标签仍然显示数字。柴堆只从结算事实读取（后果层），和 3.1 里白天的扫帚、亮灯（此刻层）分开。

### 3.4 未归类：漂流瓶（已定：点开即收起）

一个漂流瓶对应一组未归类事件（同标题算一组，和 `unclassifiedGroups` 一致）。只统计今天及以后的组，加上过去还没结算的那些；更早的由海雾和归档负责。

**点开 = 捞起**：瓶子被捞出水面后消失（0.4 秒，减弱动态效果时立即消失），同时打开这一组的归类对话框（`openClassify`，从这一组开始问）。

- 归好类：事件离开未归类，瓶子自然不会再出现。
- 点了「先跳过」或关掉对话框：瓶子也**不再漂回来**。这一组记为「已捞起」，只有出现一个**新的**未归类标题时，才会漂来新的瓶子。
- 「已捞起」只是看过的标记，不是数据：存在 `localStorage`（键 `yuzhi.drift.seen`，值为标题列表，读写都包 try/catch），不进 IndexedDB、不进备份、不跨设备。清掉浏览器数据最多让瓶子重新漂回来一次，没有其他后果。
- 归类入口不会因此丢失：追踪栏总览和「日历」对话框照常列出所有未归类事件，导入后的自动询问（`main.ts` 的 `afterImport`）也不变。

> 为什么不做成「只隐藏、不打开对话框」：瓶子是地图上唯一的归类入口。只隐藏的话，用户点一下得到的反馈只是「东西没了」，而未归类事件还在默默占用粮仓时间。捞起和打开对话框合成一步，既满足「点开就收起」，又让这一下有意义。

### 3.5 全天事件：条幅（已定：上地图）

全天事件（出差、请假、生日、截止日……）没有时刻，不参与结算，所以只属于此刻层：**今天在它的区间内就挂出来，第二天自动收起，没有任何后果。**

| 归属 | 位置 | 样子 |
|---|---|---|
| 项目 | 该村落入口，两根竹竿之间 | 屋顶色的布**条幅**，随风轻摆 |
| 杂务或未归类 | 山顶灯塔的廊台，从栏杆垂下 | 米白色条幅 |

- **为什么用条幅不用旗**：旗已经表示节日（国庆）和地标，条幅在现有画面里还没有用过，不会混淆（原则 3）。
- **多条全天事件**：每个位置最多挂 2 条，再多的在点开说明里列出（「今天：出差、团建，另外 1 件」）。
- **区间判断**：用 `[start, end)`。`ics.ts` 已经把缺少 DTEND 的全天事件补成一天，所以多天的出差会每天都挂。
- **归类**：全天事件同样走归类规则（`mergeEvents` 里的 `matchRule` 对它也生效）；但 `unclassifiedGroups` 会跳过全天事件，所以全天事件不会变成漂流瓶，没归类的就挂在灯塔上。
- **顶部日期栏**仍然追加「· 出差」文字，给读屏和不看地图的人用。
- **点开说明**：「今天全天：出差（10/3–10/6）。全天事件不需要结算，也不影响村落。」
- **夜里**：条幅不发光，不额外占用夜景的光源。

### 3.6 钟声：全岛同时只响一处（已定）

钟声是全岛唯一主动吸引注意力的效果（原则 4），所以由一个全局调度器决定谁响：

1. 候选：刚进入「即将开始」、还没响过的场次（按 `eventId` 去重）。
2. 冷却：两次钟声之间至少隔 **90 秒**（`AGENDA_BELL_COOLDOWN_SEC`）。冷却期间进入「即将开始」的场次**不补响**，直接视为已响。
3. 同一时刻有多个候选时，只响一个，按以下顺序选：当前选中的村落 → 开始时间最早的 → 槽位编号最小的。
4. 没响铃的村落照常进入「即将开始」：人照样朝井走，只是没有铃和涟漪。
5. 杂务没有钟，不参与竞争。
6. 首次加载、恢复页面、标签页从后台回到前台时，**已经处在「即将开始」的场次一律不响**（沿用 `diffScene(null, …)` 不产生提示的规则），避免一打开页面就叮当作响。

## 4. 粮仓与海雾

| 元素 | 层 | 设计 |
|---|---|---|
| 粮仓高度 | 后果层（定义不变） | 仍然是 `granary()`：全天工作时段 − 已排时间，再乘精力系数，和顶部指标卡保持一致 |
| 粮仓变化 | 转场层 | 刷新日历多出一个会议时，谷物线在 0.8 秒内降下去，同时掉下几粒谷子；不再直接跳变 |
| 粮仓门 | 此刻层 | 工作时段内有日程正在进行时，粮仓门半开，表示「正在用今天的时间」；不改变高度 |
| 海雾 | 后果层（规则不变） | `fog = min(1, 待结算天数 × 0.4)` |
| 海雾变化 | 转场层 | 补完一天的结算，雾在 1.5 秒内散开一截，不再跳变 |

> 更正上一轮的分析：之前怀疑粮仓会把跨夜事件「前一天的尾巴」错算进今天。复查 `metrics.ts:42` 后确认，被截进今天工作时段的那部分时间本来就占用了今天，算法是对的，不需要修。

## 5. 转场层：统一的「提示」管线

现在有三种互不相通的触发方式：DOM 砖块（`main.ts:206`）、`renderer.pulse()`、`setScene` 里的 `grow`。设计改成统一由 Scene 差分产生：

```ts
// src/island/cues.ts（纯函数，可测）
export type Cue =
  | { kind: 'house-built'; projectId: string }
  | { kind: 'stage-changed'; projectId: string; from: Stage; to: Stage }   // 变差：灰尘落下；变好：风吹散灰尘
  | { kind: 'granary-changed'; from: number; to: number }
  | { kind: 'fog-changed'; from: number; to: number }
  | { kind: 'bell'; projectId: string; eventId: string }                     // 即将开始，每场一次
  | { kind: 'kiln'; projectId: string };                                     // 砖坯烧成砖

export function diffScene(prev: Scene | null, next: Scene): Cue[];
```

规则：

- `prev === null`（首次加载、bfcache 恢复、读者接管后的刷新）**不产生任何提示**，直接显示终态。这沿用现有 `grow` 的 `anim: prev ? 0 : 1` 约定，并推广到所有提示。
- 钟声去重：渲染器记住已经响过的 `eventId`，只存在内存里；刷新页面不会重响。
- 结算面板里的 DOM 砖块保留（它从卡片飞出，必须在 DOM 层），但落地后的 `pulse` 改为由 `house-built` 或 `kiln` 提示驱动，`main.ts` 不再直接调用 `renderer.pulse`。
- 减弱动态效果时，`diffScene` 照常返回提示，渲染器只把时长设为 0。

## 6. 实现结构

### 6.1 新的纯函数：`src/logic/agenda.ts`

```ts
export interface AgendaSlot {
  /** 项目 id 或 CHORES */
  target: string;
  live: { eventId: string; title: string; end: string }[];   // 进行中，按结束时间排序
  soon: { eventId: string; title: string; start: string }[];   // 15 分钟内开始
  later: number;                                               // 今天稍后的场次
  ended: number;                                               // 今天已结束、尚未结算
  banners: string[];                                           // 今天挂着的全天事件标题（见 3.5）
}

export interface Agenda {
  slots: Map<string, AgendaSlot>;
  /** 未归类组的标题（今天及以后，加上过去未结算的）；「已捞起」的过滤在 UI 层做，agenda 保持纯函数 */
  drifting: string[];
  /** 杂务和未归类的全天事件标题，挂在灯塔上 */
  lighthouseBanners: string[];
  /** 今天所有全天事件标题，给顶部日期栏 */
  allDay: string[];
  /** 下一个阶段边界（开始、结束、开始前 15 分钟），用于精确安排下次刷新 */
  nextChange: Date | null;
}

export function agendaAt(data: Data, now: Date): Agenda;
```

- 只读 `data.events`、`data.entries`（用来判断是否已结算）和 `now`，不 import 任何 action，由架构测试守住这条边界（参照 `tests/action-architecture.test.ts`）。
- 新常量放进 `logic/config.ts`：`AGENDA_SOON_MINUTES = 15`、`AGENDA_BELL_COOLDOWN_SEC = 90`、`BANNERS_MAX = 2`、`DRIFT_BOTTLES_MAX = 3`、`WOODPILE_STEPS = [1, 4, 9]`。
- 跨午夜的事件：结算归属仍然按开始日期（`eventsOn` 不变）；此刻层按真实的时间区间判断是否「进行中」。

### 6.2 Scene 扩展（只加字段，不改原有字段的含义）

```ts
interface VillageView {
  // …现有字段
  agenda?: { phase: 'later' | 'soon' | 'live' | 'ended'; title?: string; until?: string; later: number; ended: number; banners: string[] };
}

interface Scene {
  // …现有字段
  chores: { count: number; woodpile: 0 | 1 | 2 | 3; live?: { title: string; until: string }; later: number; ended: number };
  /** 要画的瓶子：已过滤掉「已捞起」，最多 DRIFT_BOTTLES_MAX 个 */
  drifting: { title: string }[];
  lighthouseBanners: string[];
  granaryBusy: boolean;
}
```

`choresCount` 合并进 `chores.count`；顶部日期栏的全天事件文字在 `main.ts` 里直接读 `agenda.allDay`，不经过 Scene。

### 6.3 刷新节奏

现在是 `setInterval(update, 60_000)`。改成：每次 `update()` 之后，用 `agenda.nextChange` 安排一次 `setTimeout`（最短 1 秒，最长 60 秒），让钟声和集会准点出现，不靠每分钟轮询碰运气。只读标签页同样适用，因为此刻层不写库。

### 6.4 渲染器的改动范围

- `setScene`：调用 `diffScene` 得到提示队列；`walkers` 的目标点在 `phase === 'live'` 时改为井周围的环形位置（`retarget` 增加一个分支）。
- 新绘制函数：`drawNoticeBoard`、`drawBellRipple`、`drawGathering`（只调整站位和井边灯）、`drawUnfiredBricks`、`drawWoodpile`、`drawDriftBottle`、`drawGranaryDoor`。
- `hitAt` 新增 `{ kind: 'agenda'; target }`、`{ kind: 'drift' }`；`info.ts` 给它们写说明文字，例如「周会进行中，到 15:00。结算时确认做了，才会烧成一块砖。」

## 7. 产品决定

已定（2026-10-04）：

1. **全天事件上地图**：用条幅，项目的挂在村口，其余挂在灯塔，见 3.5。
2. **多个村落同时开会**：钟声全岛同时只响一处，90 秒冷却，不补响，见 3.6。
3. **漂流瓶点开后直接收起**：捞起即消失，同时打开这一组的归类对话框；跳过后也不再漂回来，见 3.4。

仍待定：

4. **夜里的日程**：20:30 以后进行中的事件，井边的灯是否作为夜景里的额外光源？倾向于是，效果很好看。
5. **粮仓门**会不会和粮仓高度的含义混淆？可以先只做高度转场，门放到最后一期。
6. **出差、请假类全天事件要不要降低当天的粮仓？** 现在的粮仓定义不看全天事件，挂了「出差」条幅、粮仓却显示满格，看着会矛盾。改粮仓定义属于后果层规则变更，需要单独决定，本 RFC 不做。

## 8. 不变量（写成测试）

1. `agendaAt` 的结果不会改变 `granary`、`progress`、`computeVillage`、`houseCount` 的任何输出（同一份数据，有没有此刻层，指标完全相同）。
2. 未来或进行中的事件，永远不会产生砖、房子，也不会让村落恢复。
3. 未归类事件永远不进入任何村落的 `agenda`；全天事件只进入 `banners` / `lighthouseBanners`，永远不进入 `live`、`soon`、`later`、`ended`。
4. `diffScene(null, s)` 返回空数组；`diffScene(s, s)` 返回空数组。
5. 同一个 `eventId` 的钟声在渲染器的一个生命周期里最多响一次。
6. `buildScene` 仍然只读一次时钟（`tests/scene.test.ts` 现有约束），`agendaAt` 使用同一个 `now`。
7. 钟声调度：给定任意一组「即将开始」时刻序列，任意 90 秒窗口内最多响一次，同一个 `eventId` 最多响一次（调度器写成纯函数 `pickBell(candidates, lastBellAt, selected, now)`，单独测试）。
8. 「已捞起」标记读写失败（`localStorage` 抛错或为空）时，页面照常渲染，瓶子按未捞起显示。
